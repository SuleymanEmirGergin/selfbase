# selfbase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Supabase'siz, tek compose ile kurulan backend platformu (Postgres + PostgREST + core + fn + panel) kurmak, CorteQS dev DB'sini taşımak ve CorteQS uygulamasını ona bağlamak.

**Architecture:** Dışarıya tek adres açılır: `core`. Core `/auth/v1`, `/storage/v1`, `/realtime/v1`, `/admin` uçlarını kendisi sunar, `/rest/v1`'i PostgREST'e, `/functions/v1`'i Deno `fn` container'ına aktarır, paneli de statik dosya olarak `/panel` altında servis eder. HTTP yolları ve cevap şekilleri Supabase'inkilerle aynı tutulur; böylece `selfbase-js` istemcisi `@supabase/supabase-js` yerine **alias** ile geçer ve uygulama/fonksiyon dosyaları düzenlenmez.

**Tech Stack:** PostgreSQL 17 (postgis, pgvector, pg_cron), PostgREST 12, Node 22 + TypeScript + Hono + `pg` + `jose` + `bcryptjs` + `nodemailer` + `ws`, Deno 2, React 18 + Vite, vitest, Docker Compose, Coolify.

**Spec:** `docs/superpowers/specs/2026-11-22-selfbase-design.md` (her uygulayıcı önce bunu okur)

## Global Constraints

- Runtime'da `@supabase/*` npm paketi ve `supabase/*` Docker imajı YASAK. `postgrest-js` ve supabase-js'in tip iskeleti (ikisi de MIT) kaynak olarak `client/vendor/` altına kopyalanır, LICENSE dosyalarıyla.

- SQL'de değerler parametreli, tanımlayıcılar `pg`'nin `escapeIdentifier`'ı ile. String birleştirerek SQL yok (panelin SQL editörü hariç, o bilerek ham SQL çalıştırır).
- Sırlar: hiçbir secret repoya, loga, sohbete yazılmaz. Sadece `.env.example` (boş değerli) commit edilir. `.env`, `fn.env`, `dump/`, `data/` `.gitignore`'da.

- Coolify sunucusunda başka projelere ve proxy'ye dokunulmaz. Sadece `selfbase-corteqs` kaynağı oluşturulur/değiştirilir.
- Kod, yorumlar, commit mesajları İngilizce. Commit biçimi `<type>: <description>`. Commit'ler sadece yerel `D:\Dev\selfbase` reposuna; push kullanıcı onayıyla.

3. **Storage yol kaçışı:** `../`, mutlak yol ya da `\` içeren nesne adı 400 döner, disk kökünün dışına yazılmaz. → Task 4.

5. **Panel tanımlayıcı enjeksiyonu:** tablo/kolon adı olarak `users"; drop table x; --` gönderilirse 400/404 döner, SQL çalışmaz. → Task 6.

### Task 5: Realtime + HTTP kuyruğu

**Files:** `core/src/realtime/{index.ts,hub.ts}`, `core/src/netqueue/{index.ts,worker.ts}`, `core/test/{realtime.test.ts,netqueue.test.ts}`

**Interfaces — Produces:**
- WS `GET /realtime/v1?token=<access token ya da anon key>`. İstemci → `{type:'subscribe', ref:string, schema:'public', table:string, event:'INSERT'|'UPDATE'|'DELETE'|'*', filter?:'<col>=eq.<value>'}`, `{type:'unsubscribe', ref}`, `{type:'auth', token}` (token yenileme), `{type:'ping'}`. Sunucu → `{type:'subscribed', ref}`, `{type:'error', ref, message}`, `{type:'change', ref, eventType, schema, table, new, old, commit_timestamp}`, `{type:'pong'}`.
- `hub.ts`: tek `LISTEN selfbase_changes` bağlantısı (koparsa 1 sn'de yeniden bağlanır). Bildirim gelince tabloya abone her bağlantı için `asUser(claims)` içinde `select * from <schema>.<table> where id = $1` çalıştırır; satır dönmezse hiçbir şey gönderilmez. `eq` filtresi dönen satır üzerinde uygulanır. DELETE için `old = {id}` yalnızca abonenin token'ı `service_role` ise.
